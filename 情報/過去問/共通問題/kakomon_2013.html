大問 1

アナログ／ディジタル表現・標本化と量子化・ユーザインタフェース

問1-1 — 標本化と量子化（画像のディジタル化）

問題

次の文章の空欄ア〜オを埋めよ。

ある情報を連続量として表すことをア表現と呼ぶ。これに対して、ある情報を離散的に表すことをイ表現と呼ぶ。ここで、プリントされた白黒写真をスキャンしてコンピュータに取り込む例を考える。プリントされた白黒写真はア画像なので、コンピュータで扱うためにはイ画像に変換する必要がある。そこで、空間的に連続である画像を画素（ピクセル）に分けるウの作業と各画素の明るさを離散的に表現するエの作業が必要になる。例えば、横×縦を128×128画素でウし、それぞれの画素の明るさを12ビットでエすると、この画像全体の情報はオビットで表現される。

解答を見る

「連続量そのままの表現＝アナログ」「離散的な値に区切った表現＝ディジタル」という対比がまず成り立つ（ア=アナログ／イ=ディジタル）。プリントされた白黒写真は、濃淡が空間的にも明るさの値としても連続的に変化するアナログ画像である。これをコンピュータで扱えるディジタル画像に変換するには、2段階の離散化が必要になる。

まず、空間的に連続な画像を、格子状に区切って有限個の画素（ピクセル）の集まりとして捉え直す作業がウ=標本化（サンプリング）である。次に、各画素がもつ連続的な明るさの値を、有限のビット数で表現できる離散的な値（階調）に丸め込む作業がエ=量子化である。標本化は「空間方向の離散化」、量子化は「明るさ（値）方向の離散化」という役割分担になっている。

オの計算：横×縦を128×128画素に標本化しているので、画素数は $$128\times128=16384\ \text{画素}$$ 各画素の明るさを12ビットで量子化しているので、画像全体のビット数は画素数×1画素あたりのビット数として $$16384\times12=\mathbf{196608}\ \text{ビット}$$ となる。

解ア=アナログ、イ=ディジタル、ウ=標本化、エ=量子化、オ=196608（＝128×128×12）ビット

問1-2 — GUIとデスクトップメタファ

問題

次の文章の空欄カ〜コを埋めよ。

コンピュータのインタフェースのうち、ユーザに対する情報の表示にウィンドウやメニューなどの視覚的な表示方法を多用し、それらをカなどのポインティング・デバイスを用いて操作することで、ファイル操作などの基本操作の多くを実現することができるものをキと呼ぶ。このキと対比されるものとしてクがある。これは、ユーザに対する情報を文字によって表示し、すべての操作をキーボードによって実現するインタフェースである。キの部品（構成要素）の中には、ケというコンセプトに基づいて作られているものがある。このコンセプトでは、初心者ユーザでも違和感なくインタフェースを操作可能にするには、机上に書類を広げて仕事をする感覚で「直接操作」できるようなインタフェースを提供するのが良いとされる。ケというコンセプトに基づいて作られている具体的なディスプレイへの表示方法としてコなどがある。

解答を見る

視覚的な表示とポインティング・デバイスによる直接操作を特徴とするインタフェースがキ=GUI（Graphical User Interface）であり、その操作手段の代表がカ=マウスである。これと対比される、文字表示とキーボード操作だけで完結するインタフェースがク=CUI（Character User Interface／Command-line User Interface）である。

GUIの部品の多くは、机の上に書類や文房具を広げて作業する現実世界の感覚をそのままディスプレイ上に持ち込むケ=デスクトップメタファというコンセプトに基づいている。この考え方に基づく具体的な表示例としては、ファイルやフォルダを表すコ=アイコン（書類やごみ箱を模した絵など）が挙げられる――現実の机上にある「書類」「ごみ箱」といった具体物に見立てることで、初心者でも直感的に操作の意味を理解できるようにしている。

解カ=マウス、キ=GUI、ク=CUI、ケ=デスクトップメタファ、コ=アイコン（ごみ箱アイコンなど、現実の物を模した表示）
背景知識 — 「変換」としての標本化・量子化とインタフェースの対比構造

問1-1の標本化・量子化は、いずれも「連続なもの」を「有限個の離散的な値」に落とし込む操作であるという点で共通している。標本化は連続な2次元空間を有限個の画素という格子点に落とし込み、量子化は連続な明るさの値を有限のビット数で表せる階調に落とし込む。どちらも情報を有限のビット数で表現可能にするために必須の処理であり、標本化の細かさ（画素数）と量子化の精度（ビット数）を上げれば上げるほど元のアナログ画像に近づくが、その分データ量（オのようなビット数）は増大する、というトレードオフが背景にある。また問1-2のGUI／CUIの対比は、コンピュータのインタフェース設計における「視覚的・直接操作的」対「文字・コマンド的」という大きな二分法の一例であり、デスクトップメタファは前者を初心者にも扱いやすくするための工夫として位置付けられる。

大問 2

立方根を求めるアルゴリズム — 線形探索と二分探索

問2 — 立方根アルゴリズムの空欄補充と実行回数

問題

$x>1$として、$x$の立方根を精度$\delta$（十分小さい正の数）で求めるアルゴリズムを2通り考える。

アルゴリズム(1)：

y ← 0 while (y+δ)³ < x do   ア ← ア + δ ......式(i) done return y

アルゴリズム(2)：

a ← 0 b ← x while (b−a) > δ do   c ← (a+b)/2 ......式(ii)   if c³ > x     then イ ← c     else ウ ← c   endif done return a

(1) アルゴリズム(1)の空欄アを埋めよ。
(2) アルゴリズム(2)の空欄イ、ウを埋めよ。アルゴリズム(2)は、(1)より効率の良い二分探索アルゴリズムになっている。
(3) $x=26,\delta=0.2$としてアルゴリズム(1)を実行したとき、アは式(i)により何回更新されたか。
(4) $x=26,\delta=0.2$としてアルゴリズム(2)を実行したとき、cは式(ii)により何回更新されたか。

解答を見る

(1) アルゴリズム(1)は、$y=0$から出発して$\delta$刻みで少しずつ候補を増やしていき、$(y+\delta)^3$が$x$を超えない限り更新を続けるという、総当たり的な線形探索である。ループ本体で更新されている変数はア=yであり、式(i)は「$y\leftarrow y+\delta$」を表す。

(2) アルゴリズム(2)は区間$[a,b]$を半分に絞り込んでいく二分探索である。中点$c=(a+b)/2$について、もし$c^3>x$ならば、真の立方根は$c$より小さいはずなので、上限$b$を$c$まで引き下げればよい（イ=b）。逆に$c^3\le x$（すなわちif文の条件が偽）ならば、真の立方根は$c$以上のはずなので、下限$a$を$c$まで引き上げればよい（ウ=a）。こうして区間$[a,b]$は毎回半分の幅になりながら、常に真の立方根を内部に含み続ける。

(3) 真の立方根は$\sqrt[3]{26}\approx2.9625$である。$y$は$0,\ 0.2,\ 0.4,\dots$と$0.2$刻みで増えていき、$y=0.2k$のとき条件$(y+0.2)^3<26$、すなわち$(0.2(k+1))^3<26$が成り立つ限り更新が続く。この不等式を整理すると $$0.2(k+1)<\sqrt[3]{26}\approx2.9625 \quad\Longrightarrow\quad k+1<14.8125 \quad\Longrightarrow\quad k<13.8125$$ したがって$k=0,1,2,\dots,13$の**14個**の値で条件が成り立ち、そのたびに式(i)によって$y$が更新される（$k=13$のときに更新されて$y=2.8$となり、次に$k=14$を試すと$(0.2\times15)^3=27>26$となって条件が破れ、ループが終了する）。よって式(i)による更新回数は14回である。

(4) アルゴリズム(2)では、区間の幅$b-a$は最初$26-0=26$であり、式(ii)によって$c$が1回計算されるたびに、$a$または$b$のどちらか一方が$c$に置き換わるので、区間の幅はちょうど半分になる。$n$回更新した後の区間の幅は$26/2^n$であり、これが$\delta=0.2$以下になった時点でループが終了する（それ以上更新されない）。したがって、必要な更新回数$n$は $$\frac{26}{2^n}\le0.2 \quad\Longleftrightarrow\quad 2^n\ge130$$ を満たす最小の整数である。$2^7=128<130$、$2^8=256\ge130$なので、$n=8$。すなわち式(ii)による$c$の更新回数は8回であり、このとき区間の幅は$26/256=0.1015625\le0.2$となってループが終了する。

解ア=y、イ=b、ウ=a　(3) 14回　(4) 8回
背景知識 — 線形探索と二分探索の計算量の違い

本問はまさに「線形探索 vs 二分探索」という、計算機科学で繰り返し登場する対比の好例になっている。アルゴリズム(1)は候補を$\delta$刻みで1つずつ順に試していく方式で、必要な更新回数はおおよそ（探索範囲の幅）÷$\delta$に比例する。実際、(3)では真の立方根$\approx2.9625$に達するまで$0.2$刻みでおよそ14回更新しており、これは精度$\delta$を10分の1に細かくすれば更新回数もおおよそ10倍になる、という関係にある（計算量のオーダーは$O(1/\delta)$）。これに対しアルゴリズム(2)は、区間を毎回半分に絞り込む二分探索であり、更新回数は区間の幅が$\delta$以下になるまでに要する「2で割る回数」、すなわち$\log_2(x/\delta)$のオーダーで済む（今回はわずか8回）。精度$\delta$を10分の1に細かくしても、二分探索の更新回数は$\log_2 10\approx3.3$回増えるだけであり、線形探索よりはるかに効率が良い。この「範囲を半分に絞り込むことで、更新回数を対数のオーダーに抑える」という発想は、辞書式に整列されたデータの探索など、他の多くの場面にも応用される基本的なアルゴリズム設計技法である。

大問 3（選択）

問題A：チケット予約システムとSSL／問題B：コイン投げの平均情報量

出題形式

問題A・Bのいずれか一方を選択。ここでは両方を掲載する。

問題A — チケット予約システムとSSLによる安全な通信

問題

ある利用者が、メールで届いたURLをクリックしてチケット予約サイトのページを開き、そこでクレジットカード番号を入力して決済しようとしている場面を考える。

(1) 「チケット予約システム」には、利用者の情報以外にどのような情報が保持されているか。
(2) 「個人情報の保護に関する法律」について説明せよ。
(3) メール中のURLをクリックして表示されたページでクレジットカード番号を入力することには、どのような危険性があるか。
(4) SSLやhttpsは、クレジットカード番号を安全に送信するためにどのような役割を果たしているか。
(5) メール中のURLをクリックしてから、実際にページが表示されるまでの通信の手順を、時間の流れに沿って15行程度で説明せよ。

解答を見る

(1) チケット予約システムには、利用者自身の情報（氏名・連絡先・アカウント情報や過去の予約履歴など）のほかに、予約対象そのものに関する情報――たとえば公演や興行の座席情報（空席・確保済みの別）、公演日時や会場情報、料金情報、当日の入場に用いる予約番号や電子チケットのデータなど――が保持されている。

(2) 個人情報の保護に関する法律（個人情報保護法）は、個人情報を取り扱う事業者に対し、①個人情報の利用目的をできる限り特定し公表・通知すること、②本人の同意なく目的外の利用をしないこと、③漏えい・滅失・改ざんなどを防ぐための安全管理措置を講じること、④本人の同意なく第三者に個人情報を提供しないこと、などを義務付ける法律である。これにより、利用者が安心して自分の個人情報を事業者に提供できるようにすることを目的としている。

(3) 最大の危険性は、そのURLが正規のチケット予約サイトを装った偽サイト（フィッシングサイト）である可能性を排除できないことである。本物そっくりに作られた偽ページにクレジットカード番号を入力してしまうと、番号がそのまま攻撃者の手に渡ってしまう（フィッシング詐欺）。またたとえ正規サイトであっても、通信経路が暗号化されていなければ、通信を盗聴されることでカード番号を第三者に読み取られてしまう危険性もある。メールのURLは送信者を偽装できるため、メールの見た目だけでは真偽の判断が難しい点も危険性を高めている。

(4) SSL（およびそれを用いるhttps通信）は、大きく2つの役割を果たす。第一に、ブラウザとサーバ間の通信内容を暗号化することで、たとえ通信経路上でデータが盗聴されても、クレジットカード番号などの内容を第三者が読み取れないようにする。第二に、通信を始める際にサーバ証明書を用いてサーバの身元を検証する仕組みを提供しており、接続先が本当に正規のサーバであるか（なりすましサイトでないか）を確認する手がかりを与える。この2つによって、番号の「盗聴」と「なりすまし」の両方のリスクを軽減している。

(5) 時間の流れに沿った通信手順は、概ね以下のようになる。①メールソフトでURLがクリックされたことを検知し、既定のブラウザが起動される。②ブラウザがURLを解析し、アクセス先のホスト名を取り出す。③ブラウザがDNSサーバに、そのホスト名に対応するIPアドレスを問い合わせる。④DNSサーバは、自身が答えを持っていなければルートサーバ・トップレベルドメインのサーバ・権威サーバへと階層的に問い合わせを行い、最終的なIPアドレスをブラウザに返す。⑤ブラウザは得られたIPアドレス宛にTCP接続を確立する（3ウェイハンドシェイク）。⑥httpsの場合はここでSSL/TLSのハンドシェイクが行われ、サーバ証明書の検証と、以降の通信を暗号化するための鍵の共有が行われる。⑦ブラウザはHTTPリクエスト（GETメソッドなど）を組み立て、パケットに分割して送信する。⑧パケットは経路上の複数のルータを中継されながら宛先サーバへ届く。⑨サーバはリクエストを受け取り、必要なプログラムを実行するなどしてレスポンスとなるHTMLページを生成する。⑩サーバはHTTPレスポンスとしてページのデータを返送する。⑪データはパケットに分割されてネットワークを経由し、ブラウザ側に届く。⑫ブラウザは受信した複数のパケットを正しい順序に並べ直し、元のHTMLデータを復元する。⑬ブラウザはHTMLを解析し、画像など追加のリソースが必要であれば同様の手順で追加のリクエストを行う。⑭ブラウザが取得したデータをもとに画面上にページを描画する。⑮利用者はページの内容を閲覧できる状態になる。

解(1) 座席・公演日時・会場・料金などの情報　(2) 個人情報取扱事業者に利用目的の特定・公表、目的外利用の禁止、安全管理措置、第三者提供の制限などを義務付ける法律　(3) フィッシング詐欺・盗聴によるカード番号の窃取のリスク　(4) 通信内容の暗号化による盗聴対策と、サーバ証明書によるなりすまし対策　(5) URL解析→DNS問い合わせ→TCP接続確立→（SSLハンドシェイク）→HTTPリクエスト送信→サーバでのページ生成→レスポンス返送→ブラウザでの復元・描画、という時間順の流れ
背景知識A — 「暗号化」と「認証」は別の役割

問題A(4)で見たように、SSL/httpsが果たす役割は「通信内容の暗号化」と「サーバの認証（なりすまし対策）」という、独立した2つの機能に分けて理解するとよい。暗号化だけがあって認証がなければ、通信内容自体は盗聴されなくても、そもそも偽サイトに暗号化された通信を送ってしまう（＝安全に偽サイトへ情報を届けてしまう）ことになりかねない。逆に認証だけがあって暗号化がなければ、正しいサーバに届いてはいても、その途中で盗聴されるリスクは残る。SSL/httpsはサーバ証明書による認証と、共通鍵暗号（＋公開鍵暗号による鍵交換）による暗号化を組み合わせることで、この両方の脅威に同時に対処している。問題A(3)で挙げたフィッシング詐欺は主に「認証」が欠けている（あるいはユーザがURLやアドレスバーの表示を確認しない）ことに起因する攻撃であり、SSLがあっても証明書の警告を無視して進んでしまえば防げない、という点も実務上重要な教訓である。

問題B — コイン投げの平均情報量

問題

太郎さんがコインを投げ、表が出る確率を$p$、裏が出る確率を$1-p$とする（$0\le p\le1$）。太郎さんは、投げた結果を花子さんに伝える。

(1) 花子さんが太郎さんから結果を伝えられることで得る平均情報量$H(p)$を、$p$を用いて表せ。
(2) $p=0,\dfrac14,\dfrac12,\dfrac34,1$のそれぞれについて$H(p)$の値を計算し、$H(p)$のグラフの概形について述べよ。必要ならば$0\log_2 0=0$、$\log_2 3\approx1.58$を用いてよい。
(3) 太郎さんがコインを2回投げ、その2回の結果を両方とも花子さんに伝える場合、花子さんが得る平均情報量を$H(p)$を用いて表せ。
(4) 太郎さんが、確率$q$（$0\lt q\lt1$）で結果をわざと逆にして花子さんに伝えるとする（確率$1-q$では正しく伝える）。このとき、花子さんが得る平均情報量は、(1)の$H(p)$と比べて大きいか、小さいか、同じか。理由とともに述べよ。

解答を見る

(1) 表・裏の2通りの結果がそれぞれ確率$p$、$1-p$で起こるので、平均情報量（エントロピー）はそれぞれの情報量$-\log_2 p$、$-\log_2(1-p)$を確率で重みづけた和として $$H(p)=-p\log_2 p-(1-p)\log_2(1-p)$$ と表される。

(2) 各値を計算する。 $p=0$のとき：$0\log_2 0=0$という規約により、$H(0)=0$。 $p=1$のとき：同様に$H(1)=0$。 $p=\dfrac12$のとき：$H\!\left(\dfrac12\right)=-\dfrac12\log_2\dfrac12-\dfrac12\log_2\dfrac12=\dfrac12+\dfrac12=1$。 $p=\dfrac14$のとき： $$H\!\left(\frac14\right)=-\frac14\log_2\frac14-\frac34\log_2\frac34=\frac14\times2+\frac34\times(2-\log_2 3)=0.5+\frac34\times0.42=0.5+0.315=\mathbf{0.815}$$ $p=\dfrac34$のとき：$H(p)$は$p\leftrightarrow1-p$の入れ替えについて対称（表と裏の呼び方を入れ替えただけなので当然である）なので、$H\!\left(\dfrac34\right)=H\!\left(\dfrac14\right)=\mathbf{0.815}$。 まとめると、$H(0)=0,\ H(1/4)\approx0.815,\ H(1/2)=1,\ H(3/4)\approx0.815,\ H(1)=0$となる。グラフの概形は、$p=1/2$を対称軸とする左右対称な山型（上に凸な曲線）で、両端の$p=0,1$で最小値$0$をとり、中央の$p=1/2$でちょうど最大値$1$をとる。

(3) コインを2回投げる試行は互いに独立であり、平均情報量（エントロピー）は独立な情報源については加法的である。すなわち、1回分の結果を伝えることの平均情報量が$H(p)$であるとき、独立な2回分の結果を両方伝えることの平均情報量は、単純にその2倍 $$2H(p)$$ になる。

(4) 花子さんが実際に受け取る結果を$Y$とする。太郎さんの本来の結果が表になる確率は$p$、裏になる確率は$1-p$であり、太郎さんは確率$q$で結果を逆にして伝える。花子さんが「表」と伝えられる確率$P(Y=\text{表})$は、（本来表で、正しく伝えられた場合）と（本来裏で、逆に伝えられた場合）の2通りの経路の和として $$P(Y=\text{表})=p(1-q)+(1-p)q=p+q-2pq$$ となる。これを整理すると $$P(Y=\text{表})=\frac12+\left(p-\frac12\right)(1-2q)$$ と書き換えられる（実際に展開すると一致することが確認できる）。$0\lt q\lt1$のときは$|1-2q|<1$が成り立つので $$\left|P(Y=\text{表})-\frac12\right|=|p-\tfrac12|\,|1-2q|<\left|p-\frac12\right|$$ となり、$P(Y=\text{表})$は$p$よりも必ず$1/2$（表裏が等確率という一様分布）に近づく。ところで(2)で見たように、$H$は$p=1/2$を頂点とする上に凸な関数であり、確率が$1/2$に近いほど$H$の値は大きくなる。したがって、$0\lt q\lt1$の範囲では、花子さんが実際に受け取る結果の平均情報量$H\bigl(P(Y=\text{表})\bigr)$は、元の$H(p)$よりも大きくなる（ただし$p=1/2$のときは反転してもしなくても確率は変わらないので、この場合に限り両者は一致し「同じ」になる）。なお$q=1$のとき（常に反転させる）は$P(Y=\text{表})=1-p$となり、$H(1-p)=H(p)$なので平均情報量は変化しない、という特殊なケースになることにも注意したい。

解(1) $H(p)=-p\log_2p-(1-p)\log_2(1-p)$　(2) $H(0)=0,\ H(1/4)\approx0.815,\ H(1/2)=1,\ H(3/4)\approx0.815,\ H(1)=0$。$p=1/2$を軸に左右対称な上に凸の山型。　(3) $2H(p)$　(4) $0\lt q\lt1$では大きくなる（$p=1/2$のときのみ同じ、$q=1$では変化なし）
背景知識B — 情報量の大きさと伝達の正確さは別物

問題B(4)の結果は、直感に反するように見えるかもしれない――「結果をわざと反転させる」というノイズが加わっているのに、花子さんが受け取る平均情報量はむしろ増える、というのは奇妙に思える。しかしこれは、エントロピー$H$が測っているのが「結果がどれだけ予測しにくいか（不確実性の大きさ）」であって、「花子さんが太郎さんの本来の結果を正しく知ることができたかどうか」ではない、ということを踏まえれば自然に理解できる。ノイズによって表・裏の出現確率が$1/2$に近づけば近づくほど、花子さんにとって次にどちらが伝えられるかの予測は難しくなり、その意味での情報量（サプライズの平均的な大きさ）は増加する。しかしそれと同時に、花子さんが受け取った結果が太郎さんの本当のコイン投げの結果と一致している保証は弱くなっており、「伝達の信頼性・正確さ」という観点では明らかに悪化している。このように、情報理論における平均情報量（エントロピー）は、通信路の雑音の大きさそのものではなく、あくまで受信側の記号の並びに残っている不確実性の大きさを測る量であり、雑音が多いほど不確実性が増して見かけ上のエントロピーは大きくなり得る、という点は、情報理論を学ぶ上でしばしば誤解されやすい重要な注意点である。
