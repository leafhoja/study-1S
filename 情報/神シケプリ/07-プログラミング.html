神シケプリ 07 — プログラミング

プログラム内蔵方式・擬似プログラミング言語・機械語トレースと計算量のオーダー

教科書対応箇所 pp.105-114　pp.118-119　pp.181-187

定義 — コンピュータの基本構成とプログラム内蔵方式

コンピュータは、データに対して計算処理を施す演算装置、データやプログラムを保持する 主記憶装置、主記憶装置上のプログラムに従って演算装置を駆動したり主記憶装置への データの読み書きを行う制御装置から構成される。演算装置と制御装置を組み合わせたものを 中央処理装置（CPU）という。

プログラムを他のデータと同列に扱い、主記憶装置に内蔵する方式をプログラム内蔵方式といい、 この方式を発表した人物の名前にちなんでフォン・ノイマン型コンピュータと呼ぶこともある。 プログラムをデータと同じように書き換え可能な形で保持することで、物理的な機械としての内部構造を 変えることなく、どのような計算でも行えるようになる。

定義 — 言語処理系

人間が読み書きしやすいプログラミング言語で書かれたプログラムを、コンピュータが実行できる機械語に 変換する仕組みを言語処理系という。代表的なものに次の3種類がある。

アセンブラ：機械語と1対1に対応するアセンブリ言語を機械語に変換する。
コンパイラ：高水準言語で書かれたプログラム全体を一括で機械語に翻訳してから実行する。 翻訳に時間がかかる一方、翻訳済みの機械語をそのまま実行するので実行自体は速い。
インタプリタ：高水準言語のプログラムを1行ずつ解釈しながらその場で実行する。 翻訳を待たずにすぐ実行を開始できる一方、実行のたびに解釈し直すので実行は遅い。

定義 — 擬似プログラミング言語の構文

教科書で用いられる擬似プログラミング言語の基本構文は次の4つ。

代入：変数名 ← 式（式の値を変数名に代入する）
条件分岐：if 条件 then 処理1 else 処理2 endif（条件が真なら処理1、 偽なら処理2を実行する）
反復：while 条件 do 処理 done（条件が真である限り処理を繰り返す）
出力：return 変数名（変数名の値を解として出力する）

また、通し番号（添字）を付けた変数の集合を配列といい、$x_1, x_2, \ldots$ のように 同種のデータをまとめて扱うのに用いる。

性質 — 計算量のオーダー

あるアルゴリズムについて、入力の精度やサイズを表す変数（許容誤差 $\delta$ や対象の個数など）を 変化させたとき、解を求めるのに必要な計算回数がおよそ何に比例して増えるかを表す指標を 計算量のオーダーという。反復処理を含むアルゴリズムでは、反復処理の回数が その変数に対してどう増えるかに着目すれば求められる。

典型例として、許容誤差 $\delta$ で解を求める2つの方法を比較する。反復法は $0$ から $\delta$ ずつ刻んで候補を1つずつ調べる方法で、必要な反復回数はおよそ $\dfrac{1}{\delta}$ に比例する（オーダー $\dfrac{1}{\delta}$）。一方二分法は、解の存在する範囲を 毎回半分に絞り込んでいく方法で、必要な反復回数はおよそ $\log_2\dfrac{1}{\delta}$ に比例する （オーダー $\log_2\dfrac{1}{\delta}$）。同じ精度 $\delta$ を得るのに、二分法は反復法よりはるかに 少ない反復回数で済む。

第1問

2015年度共通問題1-1 — コンピュータの基本構成の穴埋め

問題

下記の用語群の中から適切な語を選び，次の文章の穴を埋めよ．

　現在のコンピュータでは，プログラムを他のデータと同列に扱うことにより，物理的な機械としての 内部構造を変えることなく，どのような計算でも行うことができる．このような機構を 　a　方式といい，発表した人物の名前にちなんで　b 　型コンピュータと呼ぶこともある．

　a　方式のコンピュータでは，データに対して計算処理を施す 　c　装置，データやプログラムを保持する　d 　装置，　d　装置上のプログラムに従って　c 　装置を駆動したり，　d　装置へのデータの読み書きを行う 　e　装置によって構成される．　c　装置と 　e　装置を組み合わせたものを　f　装置といい， 　g　とも呼ぶ．

用語群　チューリング，フォンノイマン，制御，演算，加算，プログラム内蔵，アドレス，オペランド， パケット交換，入出力，中央処理，主記憶，CPU，CCD

解答を見る

a=プログラム内蔵／b=フォンノイマン／ c=演算／d=主記憶／ e=制御／f=中央処理／g=CPU

（判定の根拠：cは「データに計算処理を施す」装置なので演算装置。dは「データやプログラムを保持する」 装置なので主記憶装置。eは「dのプログラムに従ってcを駆動し、dへの読み書きを行う」装置なので制御装置。 fはc（演算）とe（制御）を組み合わせたものなので中央処理装置。gには用語群に残っている別名として CPUが対応する。）

解a=プログラム内蔵　b=フォンノイマン　c=演算　d=主記憶　e=制御　f=中央処理　g=CPU
第2問

2015年度共通問題3問題B — 平方根計算の機械語トレース

問題

正の実数 $x$ の平方根を計算する方法を図1に示す．アルゴリズム1は高水準言語による記述，プログラム1は それを機械語レベルで記述したものである．これらに関する以下の設問(1)〜(5)に答えよ．ただし $\sqrt3=1.73205\cdots$ であることを利用してよい．また各命令の意味は下表の通りである．レジスタや 各メモリアドレスはデータとして実数値を保持でき，また add 等の演算命令も実数を処理できるものとする．

命令意味
load AアドレスAのデータを演算レジスタに読み込む
store A演算レジスタのデータをアドレスAに書き込む
add AアドレスAのデータを演算レジスタの値に加える
multiply AアドレスAのデータを演算レジスタの値に掛ける
less_eq AアドレスAのデータと演算レジスタの値を比較し，演算レジスタの値が小さいか同じならば演算レジスタの値を1，大きければ0にする
jump AアドレスAにプログラムの実行を移す
jumpzero A演算レジスタの値が0の場合，アドレスAにプログラムの実行を移す
write演算レジスタのデータを出力する
haltプログラムの実行を停止する

【図1（1）アルゴリズム1（高水準言語）】

y ← 0
while (y+δ)^2 ≤ x do
    y ← y + δ
done
return y

【図1（2）プログラム1（機械語レベル）】

1001  load 2003
1002  add 2002
1003  store 2004
1004  multiply 2004
1005  less_eq 2001
1006  jumpzero 1011
1007  load 2003
1008  add  A
1009  store 2003
1010  jump 1001
1011  load  B
1012  write
1013  halt

2001  x の値
2002  δ の値
2003  0
2004  0

(1) アルゴリズム1を $x=3.0$，$\delta=0.03$ として実行したとき得られる結果を答えよ．
(2) アルゴリズム1を実行したとき，結果が得られるまでに実行される繰り返しの回数を $x$ と $\delta$ を用いて表せ．
(3) プログラム1を $x=3.0$，$\delta=0.03$ として実行する．アドレス1005の命令をはじめて実行する 直前の演算レジスタのデータを答えよ．
(4) プログラム1がアルゴリズム1と対応するよう，空欄　A　および 　B　を埋めよ．
(5) プログラム1を $x=3.0$，$\delta=0.03$ として実行する．1命令実行するのに0.001秒かかるとき， プログラムが停止するまでに要する時間を答えよ．導出の過程も簡単に示すこと．

解答を見る

(1) アルゴリズムは $y=0$ から $\delta=0.03$ ずつ増やしながら、$(y+\delta)^2 \le 3.0$ が成り立つ限り $y$ を更新し続ける。$n$ 回更新後は $y=0.03n$ であり、次の更新（$n+1$回目）を行うかどうかは $0.03(n+1) \le \sqrt3=1.73205\ldots$ すなわち $n+1 \le 57.7\ldots$ で判定される。$n+1=57$ （$0.03\times57=1.71\le1.732\ldots$）は条件を満たすので更新されるが、$n+1=58$ （$0.03\times58=1.74>1.732\ldots$）は満たさないので、更新は合計57回で止まる。よって 最終的な結果は $y=\mathbf{1.71}$。

(2) 更新回数は「$n\delta \le \sqrt x$ を満たす最大の整数 $n$」、すなわち $n=\left\lfloor \dfrac{\sqrt x}{\delta} \right\rfloor$ 回。

(3) プログラムをトレースする。1001 load 2003 で演算レジスタに $y$（初期値0）を読み込み、 1002 add 2002 で $\delta$ を加えてレジスタは $y+\delta$、1003 store 2004 でアドレス2004に $y+\delta$ を書き込み、1004 multiply 2004 でレジスタを $(y+\delta)\times(y+\delta)=(y+\delta)^2$ にする。ここまでで初めて1005 less_eq 2001 を実行する直前になるので、そのときの値は $x=3.0,\ \delta=0.03,\ y=0$ を代入して $(0+0.03)^2=\mathbf{0.0009}$。

(4) アドレス1007〜1010はアルゴリズムの y ← y + δ に対応する処理（$y$ を $\delta$ だけ増やして格納し直す）なので、1008の add A は $\delta$ の値が格納されている アドレスを指す必要があり、$\mathbf{A=2002}$。アドレス1011は結果としての $y$ を出力する直前の 読み込みなので、$y$ の値が格納されているアドレスを指す必要があり、$\mathbf{B=2003}$。

(5) プログラムの流れを整理すると、1001〜1006（6命令）を毎回実行して条件を判定し、条件が真 （続行）ならば1007〜1010（4命令、$y$ の更新）も実行してから1001に戻る、という1周10命令の ループになっている。(1)より、条件が真で更新まで行われる反復は57回（$n=1,\ldots,57$）。 58回目のチェックで初めて条件が偽になり、そこでは1007〜1010は実行されずに1011〜1013（3命令） に進んでプログラムが停止する。したがって命令の実行総数は

$$57\times10 + 6 + 3 = 570+9 = 579\ \text{命令}$$

（57回分のフルループ10命令ずつに加えて、条件が偽と判定される最後の1周は1001〜1006の6命令のみ、 さらに停止処理の1011〜1013の3命令）。1命令0.001秒なので、要する時間は

$$579\times0.001 = \mathbf{0.579}\ \text{秒}$$
解(1) $y=1.71$　(2) $n=\left\lfloor\dfrac{\sqrt{x}}{\delta}\right\rfloor$ 回　(3) 0.0009　(4) A=2002，B=2003　(5) 0.579秒（命令数579×0.001秒）
背景知識 — 反復法と二分法：機械語レベルで見るオーダーの違い

この問題のアルゴリズム1・プログラム1は、上の「計算量のオーダー」で触れた反復法 そのものを機械語レベルまで具体的にトレースしたものになっている。$\delta$ を $0$ から1刻みずつ 足しながら候補を1つずつ調べていくので、(5)で数えたとおり必要な命令実行回数（実質的な反復回数）は およそ $\dfrac{\sqrt x}{\delta}$ に比例する。もし同じ精度 $\delta=0.03$ を二分法 （$y^2 \le x$ を満たす範囲を毎回半分に絞り込む方式）で達成しようとすると、反復回数はおよそ $\log_2\dfrac{1}{\delta}\approx\log_2\dfrac{1}{0.03}\approx5.1$、つまり6回程度で足りる計算になり、 反復法の57回と比べてはるかに少ない反復で同じ精度に到達できる。プログラム1のような素朴な ループ構造から、探索範囲を毎回半分にする分岐構造に書き換えるだけで、計算量のオーダーが $\dfrac{1}{\delta}$ から $\log_2\dfrac{1}{\delta}$ に改善される、という好対照な具体例になっている。
